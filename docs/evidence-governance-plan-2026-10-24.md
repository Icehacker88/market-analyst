# 证据门槛、策略价值与模型版本：设计方案（2026-10-24）

作者：Claude Code。审阅：Codex。状态：**待审阅，未实施**。

背景：用户计划把 Orivane 当作买股票、基金的参考之一。这个场景下，最大的风险不是模型不准，而是**模型其实没有优势，网站却显得有把握**。本方案处理三件事，按顺序实施：

1. 提高“开始给操作建议”的证据门槛，并把不确定性显示出来；
2. 用“按信号操作 vs 一直持有”的收益来衡量信号价值，而不是只看方向准确率；
3. 给每条冻结记录标注模型版本，模型改动后战绩重新计数。

## 现状（main `842e9a7`）

- **治理状态**（`evaluateModelGovernance`，`api.mts`）：合格实盘样本少于 20 个时为 `warming_up`，使用 Safe Mode。满 20 个后，若近 20 个样本的方向优势 ≥ 1 个百分点、且没有明显衰退，就判为 `stable`，切换到 Orivane Horizon Router。
- **操作门槛**（`buildForecastAction`）：回测样本 ≥ 60、相似样本 ≥ 20、回测优势 ≥ 2 个百分点、相似命中率 ≥ 52%。实盘只在样本 ≥ 20 且优势 ≤ 0 时才否决；**实盘样本不足 20 时，实盘证据完全不参与判断**，仅凭回测就能给出可操作建议。
- **首页成绩卡**（`home-scoreboard.tsx`）：实盘样本 ≥ 20 且优势 > 0 即显示“已验证”。
- **统计**（`horizonStatistics`）只有点估计：准确率、多数类基准、优势，没有区间。
- 冻结记录有 `Best_Model`、`Model_Governance`、快照协议版本，**没有预测引擎版本**。ARIMA 第二阶段（#25）这类改动之后，新旧成绩混在一起。

**问题**：20 个样本时，方向准确率的 95% 区间宽约 ±20 个百分点。“优势 ≥ 1 个百分点”在这个样本量下基本是噪声，系统可能因为一段运气就切换模型、给出操作建议。

## 1. 证据门槛（EVIDENCE-GATE）

**统计**：`horizonStatistics` 新增字段（实盘和走步回测都算）：
- `direction_accuracy_ci_low` / `direction_accuracy_ci_high`：命中数 / 完成数的 Wilson 95% 区间；
- `direction_edge_ci_low` = `ci_low` − 多数类基准；
- `evidence`：`insufficient`（样本少于最低要求）/ `indistinguishable`（区间包含基准）/ `better`（`ci_low` > 基准）/ `worse`（`ci_high` < 基准）。

**治理**：`stable`（切换到 Router）需要同时满足：
- 当前模型版本（见第 3 节）的合格 1D 样本 ≥ `MIN_LIVE_SAMPLES = 60`；
- `evidence == "better"`，按当前版本的全部合格样本计算。

否则保持 `warming_up` / Safe Mode，理由写明“证据不足（n/60）”或“尚无法与基准区分”。`watch` / `rollback` 的保护性规则保持不变；回退只会更保守，不需要提高门槛。

**操作建议**：`actionable = true` 在现有回测条件之外，增加实盘条件：合格 1D 样本 ≥ 60 且 `evidence == "better"`。不满足时显示“仅作方向观察”，并给出明确原因：
- 样本不足：“实盘证据不足（n/60）”；
- 无法区分：“实盘表现尚无法与简单基准区分”。

**界面**：
- 战绩页和资产页的准确率旁显示区间，例如“58%（95% 区间 41–74%）”，并给一句结论：尚无法与基准区分 / 显著优于基准 / 显著差于基准。
- 首页“已验证”改用同一规则。
- 进度条改为 n/60。

**影响**：按每个资产每个交易日 1 个样本计算，最快约 3 个月才可能出现操作建议；如果模型确实没有优势，会一直不出现。对真实资金使用者来说，这是有意的取舍。

**用户已确认（2026-10-24）**：门槛采用当前版本 ≥ 60 个合格样本，且 Wilson 95% 区间下限高于多数类基准；不采用放宽方案。

## 2. 策略价值（STRATEGY-VALUE）

对每条已结算、时间资格合格的 1D 记录，按日计算以下策略的收益：

| 策略 | 每日收益 |
| --- | --- |
| 一直持有（基准） | `Actual_1D_Return` |
| 只做多（适合买基金） | 预测上涨则持有：`Actual_1D_Return`，否则 0 |
| 按方向多空 | `sign(Forecast_1D_Return) × Actual_1D_Return` |
| 只按可操作信号 | `Action_Signal` 为 Up/Down 时按方向操作，否则 0 |

- **成本**：每次仓位变化扣除 `TRADE_COST_BPS = 5`（0.05%，可配置）；同时显示扣成本前后两种结果。
- **指标**：累计收益、相对一直持有的差值、交易次数、胜率、最大回撤。样本不足 60 时只显示数值，并标注“样本不足，不能作为结论”。
- **计算位置**：服务端统计（与 `horizonStatistics` 同处），新增 `strategy_comparison`，前端只负责展示，保证首页、战绩页、资产页口径一致。走步回测也算一份，但必须明确标注“回测（模拟）”，与实盘分开显示。
- **口径说明**：实盘结算使用不含分红的价格收益，一直持有的收益因此略被低估，界面上会写明。第一期只做 1D；5D/10D/1M 的持有期互相重叠，复利和成本的计算需要另行设计。

**界面**：战绩页新增“如果按信号操作”一节：各策略的累计收益曲线和一张表，结论用平实语言写，例如“过去 n 个交易日，只做多策略扣成本后比一直持有少 x%”。

## 3. 模型版本（MODEL-VERSION）

- 冻结时在记录里写入 `Model_Version`，取值为 `cloud-forecast-<ENGINE_VERSION>`（云端）或 `python-pipeline-<PIPELINE_VERSION>`（日报账本）。版本号常量放在代码里，**凡改动预测逻辑的 PR 必须同时把版本号加一**；PR 模板增加一项检查，AGENTS.md 增加一条规则。
- 旧记录没有版本号，统一视为 `legacy`，不回填。
- `horizonStatistics` 支持按版本过滤：治理和操作门槛只使用**当前版本**的样本，所以模型一改，证据就重新累积；战绩页默认显示当前版本，可切换查看全部版本。
- 第 1 节的“最低 60 个样本”按当前版本计算。
