# 证据门槛、策略价值与模型版本：设计方案（2026-10-24，第 2 版）

作者：Claude Code。审阅：Codex。状态：**门槛已由用户确认；第 2 版按 Codex 审阅（[#35 评论](https://github.com/Icehacker88/market-analyst/pull/35#issuecomment-6371899292)）修订，待复核，未实施**。

背景：用户计划把 Orivane 当作买股票、基金的参考之一。最大的风险不是模型不准，而是**模型其实没有优势，网站却显得有把握**。本方案包含三部分：

- **证据门槛**：模型切换和操作建议必须先通过统一的证据门；
- **模型版本**：只统计当前版本的样本。这是证据门的前提，所以**云端部分先做或同批上线**；
- **信号价值**：用假设性收益评分，对比“按信号操作”和“一直持有”。

**用户已确认的门槛（不再变动）**：每个资产、当前云端预测政策版本下，至少 60 个合格且已结算的 1D 样本；并且命中率 Wilson 95% 下限**严格高于**同一批样本的多数类基准。

## 现状（main `842e9a7`）

- **治理**（`evaluateModelGovernance`）：
  - 近 20 个合格样本不足 20 个 → `warming_up`。
  - 满 20 个后：近 20 个样本优势 ≤ −3，或衰退明显 → `rollback`；优势 < 1，或衰退 ≥ 6 → `watch`；否则 → `stable`。
  - 对外的 `active_model`：`warming_up` 和 `rollback` 为 Safe Mode，`watch` 和 `stable` 为 Router。
- **Safe Mode 的实际作用**（`cloudTrendForecast`）：`safeMode = rollback || warming_up`。因此 **`watch` 仍然运行 Router，并允许每日调权和 Kronos/事件叠加**，只是禁止候选模型晋级。这意味着在 20 个样本、优势为 0 时就可能离开保守配置。
- **操作门槛**（`buildForecastAction`）：
  - 条件包括新鲜度、1M 预测幅度、置信度、回测样本 ≥ 60、相似样本 ≥ 20、回测优势 ≥ 2、相似命中率 ≥ 52%。
  - 实盘证据只在“样本 ≥ 20 且优势 ≤ 0 或为空”时才否决；实盘样本不足 20 时，这个函数不会因实盘证据否决。（整个预测流程的其他环节仍会用到实盘统计。）
- **首页成绩卡**（`home-scoreboard.tsx:19`）：只有在回测优势 > 0、实盘合格样本 ≥ 20、实盘优势 > 0 时，才隐藏“当前模型尚未证明优于简单基准”这句提示；**不会显示“已验证”标签**。首页把 SPY/QQQ/NVDA 三个资产合在一起统计。
- **统计**（`horizonStatistics`）：只有点估计（准确率、多数类基准、优势），没有区间。
- **冻结记录**：有 `Best_Model`、`Model_Governance`、快照协议版本，**没有预测政策版本**。预测缓存最多复用 30 小时，`applyCurrentForecastGuard` 使用缓存里旧的 validation。

## 1. 云端预测政策版本（MODEL-VERSION-CLOUD，证据门的前提）

**版本代表什么**：`CLOUD_FORECAST_POLICY_VERSION`（例如 `cloud-forecast-policy-v1`）代表**整套自适应预测政策**，包括：
- Safe Mode 组合；
- Router 和每日调权规则；
- 候选模型集合和晋级规则；
- 叠加信号；
- 特征和数据口径；
- 输出格式。

它**不**代表某个具体候选模型。因此：
- 日常的重新拟合、路由切换、调权**不升版本**；
- 战绩只能说明“这套政策”的表现，界面不能宣称某个候选模型已经通过实盘验证。
- 如果以后要证明某个候选模型本身，需要另行定义它自己的样本，不在本方案范围内。

**何时升版本**：凡是改变预测输出、候选集合、选模或路由规则、特征、数据口径、门槛配置的 PR，都必须升版本。
- 例外：输出完全一致的性能优化（例如 #32）可以不升，但必须附带新旧逐值等价的测试。
- 云端和 Python 各自独立升版本：Python ARIMA 的改动不会重置云端证据。
- AGENTS.md 增加这条规则，PR 模板增加一个勾选项。

**版本在哪里确定、如何传递**：
- 版本在**生成预测时**写入预测对象 `policy_version`，并原样随不可变 publication 存档、预测缓存和账本记录（`Policy_Version`）传递。
- 读缓存时，如果 `policy_version` 不等于当前版本（包括没有版本的 legacy 缓存），一律视为过期并重新生成，**绝不给旧结果补贴新版本号**。
- 旧版本的统计和 validation 不得用于给新版本解锁。
- 旧账本记录不回填，统一视为 `legacy`。

**统计对象**：每个资产、`Policy_Version == 当前版本`、`outcomeEligible(row, "1D")` 为真的已结算记录，每个基准日最多计 1 条（同日只会有一条合格记录，实现时仍做去重）。**不跨资产相加**：首页的三资产汇总不能用来说明“某个资产已经达标”。

## 2. 证据门槛（EVIDENCE-GATE）

**唯一的证据门**：`evidence_gate_passed(asset)` = 当前版本合格样本数 n ≥ 60，并且 `wilson_low_95(命中数, n) > 同一批样本的多数类基准`。

**状态优先级**（从高到低，取第一个满足的）：
1. `rollback`：沿用现有的保护性规则（近期优势 ≤ −3 或明显衰退），**可以在证据门之前触发**，因为降级只会更保守。
2. `warming_up`：证据门未通过。理由写明“证据不足（n/60）”或“尚未达到既定证据门槛”。
3. `watch`：证据门已通过，但出现现有 watch 条件。
4. `stable`：证据门已通过，且没有 watch 条件。

**行为**：
- 证据门未通过（`warming_up`）或处于 `rollback` 时：
  - 使用 Safe Mode；
  - **禁止** Router 晋级、每日调权、未经验证的叠加信号；
  - `actionable = false`。
- `cloudTrendForecast` 的 safeMode 判断改为 `active_model === Safe Mode`，不再枚举状态名，避免以后新增状态时绕过。
- `watch`（证据门已通过）保持现有含义：可以运行 Router，禁止候选晋级。
- `actionable` 在现有条件之外，增加“证据门已通过”。

**统计字段**：`horizonStatistics` 增加 `direction_accuracy_ci_low/high`（Wilson 95%）、`evidence_gate`（`insufficient` / `not_met` / `met`）以及计数用的版本。走步回测也计算区间，但只用于展示，不参与门槛。

**界面措辞**：
- 用“达到既定证据门槛 / 尚未达到”，不写“显著优于基准”。
- Wilson 下限与样本内多数类基准的比较，不等于配对差异的显著性检验；多资产之间相关、每天重复检查，也都没有整体 95% 的保证。界面要说明这条规则是保守的使用门槛，而不是统计结论。
- 战绩页和资产页显示“58%（95% 区间 41–74%）”这样的区间，进度显示每个资产 n/60。
- 首页沿用现有提示句，只有三个资产**都**达到门槛时才隐藏，并分资产显示进度。

**上线后的影响**：最快约 60 个交易日（约 3 个月）后，才可能出现操作建议和 Router；如果模型一直没有优势，就会一直保持 Safe Mode。

## 3. 信号价值（STRATEGY-VALUE）

**第一期只做“假设性收盘价评分”，并明确标注不可执行。**

合格预测最早在基准日收盘 15 分钟后才生成，而结算收益从基准日收盘价算起；收到信号后，实际最早只能在下一交易日开盘进场。所以这个评分**不是可执行的交易回报**。

界面统一标题为“假设性收盘价评分（非真实交易收益）”，并写明这一点。可执行的模拟（例如以目标交易日开盘价进场，并保存开盘价的行情证据）留到第二期另行设计，不复用现有结算收益。

**对象**：单个资产、1D、当前政策版本。**不跨资产拼接**，在定义组合权重之前不计算组合。

**日期序列**：
- 从该资产当前版本的第一条合格记录开始，到最近一条已结算记录为止，逐个交易日（按已核验日历）计算。
- 每天的市场收益 `r_t` 取该资产当天的收盘价收益，来自价格历史，和有没有合格记录无关。这样基准不会因为缺记录而失真。
- 某个交易日没有合格且已结算的记录时，信号类策略当天的仓位为 0（视为没有信号，空仓）；这类日子单独计数并显示。

**仓位与成本**：

| 策略 | 仓位 `w_t` |
| --- | --- |
| 一直持有（基准） | 1 |
| 只做多（适合买基金） | 预测 1D 上涨为 1，否则为 0 |
| 按方向多空 | 预测上涨为 +1、下跌为 −1，预测为 0 时为 0 |
| 只按实盘可操作信号 | `Action_Signal` 为 Up/Down 时为 ±1，否则为 0 |

- 初始仓位 `w_{-1} = 0`。
- 成本 `cost_t = 0.0005 × |w_t − w_{t−1}|`：0→1 扣 5bps，1→−1 扣 10bps，仓位不变不扣。
- 基准只在第一天扣一次 5bps 的买入成本。
- 期末不强制平仓，按市值计；另外显示一个“含平仓成本”的数值。
- 空仓日收益为 0，不计现金利息。
- 净值递推：`NAV_t = NAV_{t−1} × (1 + w_t × r_t − cost_t)`，`NAV_{-1} = 1`。
- 交易次数 = `w_t ≠ w_{t−1}` 的天数；胜率 = `w_t ≠ 0` 的天数中 `w_t × r_t > 0` 的比例。

**“只按可操作信号”的范围**：只对实盘有定义。走步回测里同名的 `Action_Signal` 来自 `trend.signal`，并没有复现实盘的操作门槛，所以回测只显示“只做多”和“按方向多空”，不显示这一项。也不用今天的 60 样本门槛去倒推历史上的操作信号。

**指标与限制**：
- 指标：累计净值、与一直持有的差值、交易次数、胜率、最大回撤；同时显示扣成本前后两种结果。
- n < 60 时标注“样本不足，不能作为结论”。
- 所有策略都只用**价格收益**：做多会漏掉分红，做空没有扣除需要补付的分红，可能高估做空收益，影响大小无法保证。
- 5bps 只是一个设定，不包括借券、融资和其他费用，也不代表基金的真实交易成本。
- 这些限制都要在界面上写明。

| MODEL-VERSION-CLOUD：政策版本的生成、传递、缓存失效、按版本统计；AGENTS.md 和 PR 模板规则 | Claude Code | Codex | 第一个做 |
| EVIDENCE-GATE：Wilson 字段、唯一证据门、状态优先级、safeMode 判断改造、操作门槛、界面 | Claude Code | Codex | 依赖 MODEL-VERSION-CLOUD（可以在同一个 PR 里一起上线，但不能先于它上线） |
| STRATEGY-VALUE：假设性收盘价评分的计算和战绩页章节 | Claude Code | Codex | 等 EVIDENCE-GATE 的统计接口合并后再串行做（两者都改 `api.mts` 的统计接口） |
| MODEL-VERSION-PY：Python 日报账本加 `Policy_Version` 列，规则与云端一致、版本号独立 | Codex | Claude Code | 和云端共用字段约定；可以独立推进，不阻塞云端 |

每个任务各自开分支、提 PR、交叉审阅；合并和部署分别需要用户授权。上线后网站行为的变化在各自 PR 中写明。

## 不做的事

- 不改变预测模型本身，也不调参。
- 不回填、不改写历史记录。
- 不给出个性化投资建议，网站文案继续写明仅供参考。
- 第一期不做可执行模拟、多资产组合、5D/10D/1M 的策略评分。
