# 模型预测效果只读诊断（2026-10-17）

作者：Claude Code。只读分析：没有修改模型代码，没有触发 optimizer、Kronos 或任何生产任务。数据来源均为公开接口或仓库文件，可按文末命令复现。

## 结论

1. **网站云端预测的主要问题在 "Orivane Ensemble Safe Mode"。** 8 月 4 日起，治理逻辑把模型从 Horizon Router 回滚到 Safe Mode；9 月以后只剩 Safe Mode。Safe Mode 的 1D 命中率 37.5%（72 条），5D 33.3%（66 条）。它替换掉的 Horizon Router 是 51.5%（66 条）和 57.6%（66 条）。
2. **回滚有粘性，并且没有和被替换的模型比较。** 回滚只看当前模型最近 20 个样本的方向优势是否为负；进入回滚后，只要最近 20 个样本的方向优势低于 +3 个百分点，就一直停在回滚状态。Safe Mode 本身更差，所以一直满足留在回滚的条件，等于被锁在更差的模型上。代码位置：`股票预测/frontend/netlify/functions/api.mts` 的 `evaluateModelGovernance()`（产品分支约第 4665–4690 行）和 `safeMode` 分支（约第 5262 行起）。
3. **Python 日报账本的问题在 ARIMA 的看涨偏向。** ARIMA 承担了 67% 的预测，命中率 46.8%，其中 72% 预测为涨；而样本期内实际只有 45.5% 的交易日上涨。按"永远猜跌"计算的基准是 54.5%，高于整体命中率 51.9%。
4. **幅度和置信度：** 账本中预测幅度最大的四分之一命中率为 60%，最小的接近随机。云端预测的 `Confidence_Score` 分三档后，命中率分别为 44%、38%、49%，没有区分能力。

## 局限

- 样本量小。三个标的在同一天高度相关，有效独立样本大约等于交易日数（云端约 73 天，Safe Mode 期间约 24 天）。5D、10D、1M 的窗口互相重叠，有效样本更少。上述差异属于强信号，但没有做严格的显著性检验。
- 只看了冻结后已结算的记录，没有重跑模型，也没有查看 Safe Mode 内部各组成部分的方向。
- 命中率低于 50% 不等于预测方向反了。不过 Safe Mode 期间 5D 命中率只有约 22%，值得优先排查符号或组合方式。

## 建议（需 Codex 评估，改动生产预测逻辑前需用户同意）

1. 排查 Safe Mode 的趋势集成（`trendForecast` 在不调权、无叠加信号时）有没有符号或组合方式问题。
2. 回滚期间继续以影子模式计算 Horizon Router 和 Kronos 的预测并冻结记录。是否退出回滚，看几个候选的实时优势对比，而不是只看当前模型自己的历史。
3. 所有候选的实时优势都为负时，退回到多数类基准，或者直接弃权（只显示"观察"），不发布方向。
4. Python 日报：检查 ARIMA 的看涨偏向，考虑在选模时加入方向基准比较，或者对小幅度预测弃权。
5. 置信度分数目前没有区分能力，在重新校准之前，页面上应弱化它的展示。
