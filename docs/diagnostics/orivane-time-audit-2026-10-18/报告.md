## 代码层已确认缺口

1. **结算只看 As_Of_Date，不看预测是否先于结果产生。** Python `_reconcile_actuals` 与云端 `reconcileCloudLedger → attachActualOutcomes` 都从基准日后的行情选目标。生成很晚的记录仍会被结算；云端 `Verified` 仅代表已有 Actual_1D_Return。纯离线调用实际函数已复现：目标收盘后生成的预测仍被标 Verified。
2. **后读行情可改变收益基准。** 两条链路都从后来读到的历史行情选基准价；云端每次可能重算结果。实际函数离线测试中，同一预测和目标价 110，仅把基准价从 100 改为 105，收益就从 10% 变成约 4.76%。这验证的是缺少固定价格基准的风险，不是说这些样本已全部发生价格修订。
3. **生成时间证据不够精确。** Python Created_At 用整个日报启动时间，早于逐资产模型完成和写入；云端 Created_At 采用 forecast.generated_at，没有独立 frozen_at 证明首次不可变提交时间。临界样本不能靠现有字段恢复精确可用时间。
4. **模型验证存在另一组独立问题。** ARIMA `predict(x)` 只用 len(x)，不使用预测日期；TimeSeriesSplit gap=1 与次日收益目标组合时存在预测步数错位。整段多步外推又不同于每日滚动一步。选模分数还混入最终测试段 Return_RMSE/MAPE，因此该测试段并非独立最终检验。异常回退至中位数时没有明确模型失败标记。
5. **治理会继承不合格成绩。** 云端 horizonStatistics 只要求结果与正确性字段存在；不做生成时间资格筛选，治理统计随之受影响。但这不能推出 Safe Mode 一定不应启用，也不能据此直接指定新的赢家模型。

## 推荐修复顺序

### 第一阶段：P0，时间资格与不可变快照（复杂度中高）

修改范围：`股票预测/src/prediction_ledger.py`、`daily_report.py`、必要的数据清洗/交易时段校验、`股票预测/frontend/netlify/functions/api.mts` 及相应测试。通过既有 Worker 生成器验证兼容，不单改生成文件。

- 明确模型协议：日收盘基准、目标交易时段、允许发布时间截止点。建议收盘后生成的次日研究预测必须在目标常规交易时段开始前完成冻结；盘中预测另立协议，不能冒充完整下一交易日预测。
- 新记录固定基准价格、复权/未复权口径、源数据时间、取数时间、实际生成完成时间、首次冻结时间、目标时段和协议版本。基准与目标必须同口径；旧记录缺字段标未知，不伪造历史冻结时间。
- 分开“已得到实际结果”和“可计入事前成绩”。晚生成、基准未完成、交易时段未知、价格口径无法对齐分别给原因。按 horizon 判资格；1D 不合格不能直接推断所有长周期都合格或都无效，已部分发生的 5D 窗口也不能当完整事前 5D。
- 数据陈旧时不伪造新的 data_as_of，不用旧日基准结算已发生的一日；跳过该资产或只提供明确过时的研究展示，其他资产继续。
- 资格过滤统一用于成绩和模型治理。保留历史原账本，先生成独立资格报告/版本化成绩；任何生产回填或写入另行授权。
- 对旧样本，只有证据足够才恢复资格。不能仅因不在这 46 条中就默认合格。

验收：46 条均被拒绝计入对应 1D 成绩；21 条待核验与 VIX 日历问题有独立原因；覆盖周末、节假日、夏令时、提前收盘、晚生成、盘中未完成 K 线、复权价格修订和不明确时间；历史原值不变；合格基准样例仍正确结算。报告排除数量，不能只展示过滤后的更好成绩。

### 第二阶段：P1，修复 ARIMA 验证与选模（复杂度中）

修改范围：`股票预测/src/models.py`、调用预测/评估的代码与测试。

- 用实际 target 日期验证一步预测对齐，保留防泄漏 gap，不通过删除 gap 掩盖错位。
- 采用逐日滚动预测；每步只能使用当时可用数据。所有候选用同一资产、日期、标签口径对比。
- 内层时序验证负责选模；外层留出集只做最终报告，不再反向参与评分选模。
- ARIMA 拟合失败显式记录 fallback 与原因；回退结果不能继续冒充正常 ARIMA 成功。
- 继续报告已有多数类基线、balanced accuracy、directional edge，并保留误差和样本数。

验收：用可预测的合成序列与缺日序列证明日期对齐；验证任何未来数据变化不影响此前预测；fallback 可见；留出集指标变化不改变已选模型；新旧方法使用同一合格样本集比较。

### 第三阶段：P1，重算治理与有限候选评估（复杂度中）

- 第一、二阶段完成后才重算治理输入，确保模型标签与实际执行路径一致。
- 有效样本不足时明确提示，不自动解除 Safe Mode。
- 先离线比较现有候选，再收集新的事前样本；不能根据本次历史区间直接调权并宣称提升。
- 测试降级、退出、重新进入及未知数据时的保守行为；生产应用另行授权。

不建议这轮同时重写模型架构、引入新后台任务或改变首页、认证、只读 Snapshot。
